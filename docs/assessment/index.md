# 評価の進め方

成熟度モデルを使って自組織・自サービスを評価する手順と、評価レポートの書き方です。評価は **軸ごとに独立** に行い、レベルは「そのレベルの定義を満たしていると証跡で示せる最高のレベル」とします。

## 基本的な手順

1. **評価対象と範囲を決める** — 組織・チーム・プロジェクト・サービスのどの単位を評価するか（[名称定義](../model/#名称定義)）。複数サービスをまとめて評価する場合はサービスごとに差があることを前提にする。
2. **軸ごとに現状を確認する** — [成熟度モデル](../model/)の各軸ページで、レベル1から順に「説明」「具体例」と現状を照らし合わせる。
3. **証跡を集める** — 設定ファイル、ダッシュボード、手順書、インシデント記録、KPI のレビュー記録など。「やっているつもり」と「記録がある」を区別する。
4. **レベルと確信度を決める** — 証跡で直接確認できる最高のレベルを採用する。上位レベルの取り組みが一部あるだけでは上げない。レベル3以上は「組織全体で一貫して適用されているか」の確認が必要。
5. **次のレベルへのアクションを決める** — 各軸ページの「レベル N→N+1 に進むには」から、改善アクション（必須）を優先し、活用アクション（推奨）を状況に応じて選ぶ。注意点メモを読む。
6. **定期的に再評価する** — 半期〜年次で同じ手順を繰り返し、レベルの推移とアクションの完了状況を見る。

## 判定で迷いやすい点

- **レベルは積み上げ** — レベル3の要件を満たすにはレベル2の要件も満たしている必要があります。
- **ツールの導入 ≠ レベル到達** — 異常検知ツールを入れただけでは「動的しきい値でノイズを削減している（A4 レベル3）」とは言えません。運用されていて効果が出ていることが要件です。
- **組織標準化（レベル3）は横断性が要件** — 1 チームが整備していても、組織全体で標準として適用されていなければレベル2〜3の間と判断し、ギャップとして記録します。
- **定量管理（レベル4）は「測って、判断に使っている」こと** — KPI を定義しただけでは不十分で、測定結果に基づく調整・判断の記録を求めます。
- **対象外の軸** — 例えば内部向け API のみのサービスでは「ユーザー行動の理解と最適化」が対象外になることがあります。無理にレベル1にせず「対象外」と記録します。

## 評価レポートのテンプレート

人手で評価レポートを書く場合は [評価レポートテンプレート](report-template.md) を使ってください。

## リポジトリから下書きを自動生成する（Claude Code スキル）

このリポジトリには、Claude Code 用の Agent Skill `observability-maturity-assessment` が同梱されています。対象リポジトリ（ローカルパスまたは GitHub URL）を走査し、設定・コード・文書を証跡として 6 軸の **暫定レベル・確信度・ギャップ・ヒアリング質問・改善アクション** を含む評価レポートの下書きを生成します。

```text
.claude/skills/observability-maturity-assessment/
├── SKILL.md                      # 手順（Claude が読む）
├── scripts/
│   ├── scan_repo.py              # リポジトリ走査 → evidence.json / evidence-summary.md（判定はしない）
│   ├── build_report.py           # assessment.json + CSV → レポート Markdown
│   ├── omm_model.py              # CSV パーサ（docs 生成と共用）
│   └── signals.json              # 証跡シグナルのカタログ（6 軸 × レベル目安）
└── references/
    ├── evidence-rubric.md        # 証跡 → レベル判定ルーブリック
    ├── interview-questions.md    # リポジトリから確認できない事項のヒアリング質問
    ├── assessment-schema.md      # assessment.json の形式
    └── csv/                      # モデル CSV の同梱コピー（tools/build_docs.py で同期）
```

使い方（Claude Code をこのリポジトリで起動した状態で）:

```text
/observability-maturity-assessment https://github.com/org/your-service を評価して
```

他のリポジトリで使う場合は `.claude/skills/observability-maturity-assessment/` を対象リポジトリの `.claude/skills/` か `~/.claude/skills/` にコピーします。モデル本文は同梱 CSV から引用されます。

> 生成されるのは**下書き**です。成熟度モデルの要件の多くは組織・運用の実態に関するもので、リポジトリだけでは確定できません。レポートの「ヒアリング質問」への回答を得てから最終評価としてください。
