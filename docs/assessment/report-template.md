# 評価レポートテンプレート

人手で評価する場合のテンプレートです。Claude Code スキルが生成するレポートも同じ構成になっています。コピーして使ってください。

```markdown
# オブザーバビリティ成熟度評価: <対象名>

## 評価対象

| 項目 | 内容 |
|---|---|
| 対象 | <組織 / チーム / プロジェクト / サービス名> |
| 範囲・前提 | <評価に含めた範囲、含めなかった範囲> |
| 評価日 | YYYY-MM-DD |
| 評価者 | <氏名 / チーム> |
| 情報源 | <ヒアリング相手、参照した設定・記録> |

## サマリ

| 評価軸 | レベル | 確信度 | 次のレベル |
|---|---|---|---|
| A1. データ収集と可視化 | レベルN（名称） | 高/中/低 | レベルN+1 |
| A2. システムの信頼性管理 | | | |
| A3. 開発・運用プロセスの整備と最適化 | | | |
| A4. アラート最適化と障害対応 | | | |
| A5. ユーザー行動の理解と最適化 | | | |
| A6. 継続的な改善と最適化 | | | |

### 総評

<全体傾向、強み、最初に取り組むべき軸とその理由>

### 優先して取り組むテーマ

1. [軸] テーマ — 理由
2. ...

## 軸別の評価

### A1. データ収集と可視化

- **レベル**: N（名称） / **確信度**: 高・中・低
- **判定理由**: <満たした要件と、次レベルに達しない理由>
- **証跡**:
  - <設定ファイル / ダッシュボード / 手順書 / 記録へのリンク> — 何を示すか
- **次のレベルとのギャップ**:
  - <モデルのレベルN+1の定義と比べて不足している点>
- **未確認事項**:
  - <今回確認できなかったこと>
- **次のアクション**（モデルの改善アクションプランから選択・具体化）:
  - 改善アクション（必須）: ...
  - 活用アクション（推奨）: ...

（A2〜A6 も同じ構成）

## 付録: 評価方法

- レベルは「定義の主要要件を証跡で直接確認できる最高のレベル」とした。
- 確信度: 高 = 複数種類の一次証跡で主要要件を直接確認 / 中 = 一部が口頭・文書のみ / 低 = 主に推定。
- 本評価のレベル定義・改善アクションは DMM.com LLC の
  オブザーバビリティ成熟度モデル（CC BY 4.0）に基づく。
```

## 書き方のポイント

- **判定理由は「満たした」と「満たしていない」の両方を書く** — 「レベル2の要件 X・Y は確認できた。レベル3の要件 Z（組織標準）は未確認」のように、次のレベルの定義に照らして書くとギャップが自明になります。
- **証跡は第三者が確認できる形で** — ファイルパス、ダッシュボードの URL、記録の所在。口頭のみの情報はその旨を明記します。
- **確信度を正直に** — 評価は改善のためのものです。高めに出すことに意味はありません。
- **レベルの平均を出さない** — 軸ごとに独立に扱い、「どの軸から着手するか」の判断に使います。
