# A1. データ収集と可視化

**能力の定義**: システムのあらゆる領域に関するデータを網羅的に収集し、リアルタイムで可視化・分析できる能力。

<a id="level-1"></a>
## レベル1: 属人的

**説明**

データ収集と可視化は個人の裁量に依存しており、対象範囲や手法は定義されておらず、一貫性もない。記録や手順も未整備で、場当たり的な運用にとどまっている。

**具体例**

サーバのCPU・メモリ使用率のみを監視しており、アプリケーションログは一部のみ収集している。可視化はシンプルなグラフに限られ、異常検知は手動で行っている。

<a id="transition-1-2"></a>
### レベル1→レベル2 に進むには

**改善アクション（必須）**: CPU、メモリ、ディスク使用率など、インフラ領域の基本的なメトリクスを明確化し、標準的な監視ツールを用いて定期的な収集を開始します。また、リアルタイムで主要指標を把握できる簡易ダッシュボードを構築し、担当者によるモニタリング体制を整備します。

**活用アクション（推奨）**: 次のステップとして、アプリケーションログや基本的なリクエスト系メトリクス（リクエスト数、エラー率、レスポンス時間など）を追加収集します。加えて、指標の名称・単位・タグ設計の標準ルールを定め、週次または月次でデータの見直しを行う運用ルールを定着させます。

> **注意点メモ**: 初期段階では過剰に収集対象を拡げすぎないことが重要です。重要指標に優先度をつけ、データの欠損や取得失敗がないよう安定的に収集できる体制から始めましょう。

<a id="level-2"></a>
## レベル2: プロセス確立

**説明**

主要システムに対して、基本的なメトリクスやログの収集・可視化に関する管理プロセスが導入されている。収集手順や品質確認も実施されているが、データの統合やリアルタイム性には課題が残り、プロジェクト単位での実施にとどまっている。

**具体例**

メトリクス収集・可視化の手順書を整備し、担当と実施頻度を明確にしている。アプリケーションやネットワークのデータはツールごとに分断されており、更新頻度が低いため即応性に欠けている。データ品質の点検も実施しているが、ツールや手法はチームごとに異なっており、一貫性は限定的である。

<a id="transition-2-3"></a>
### レベル2→レベル3 に進むには

**改善アクション（必須）**: インフラ、アプリケーション、ネットワーク、データベース層を含むすべての主要なコンポーネントに対してモニタリング対象を拡張します。また、収集間隔を1分以内に設定するなど、リアルタイム性を意識したモニタリング体制を整備します。さらに、収集設定の見直しや、想定通りのメトリクスが取得・可視化できているかを定期的に確認し、設定漏れやタグ不足などによるモニタリングの抜けを防ぎます。

**活用アクション（推奨）**: 各システムに対して、可用性や性能に関する重要なモニタリング指標を整理・設計します。さらに、外部要素（CDNのレスポンスタイムや外部APIの可用性など）も監視対象に追加し、システム全体の健全性を把握できる体制を構築します。収集データの欠損検知やエージェントの死活監視など、データ品質を保つ仕組みも併せて整備します。

> **注意点メモ**: モニタリング対象が偏らないように、インフラ、アプリ、ネットワーク、データベース層のすべてをバランス良く監視することが重要です。必要以上に収集対象を拡げるとコスト増につながるため、重要度を考慮して監視対象を取捨選択することも忘れずに行ってください。

<a id="level-3"></a>
## レベル3: 組織標準化

**説明**

組織標準として統一されたデータ収集・可視化プロセスが文書化され、インフラ・アプリ・ネットワーク・DB層に一貫して適用されている。可視化基準や品質管理も共通ルールとして定着している。

**具体例**

DatadogやNew Relicなどを使い、全層のモニタリングを標準プロセスに沿って実施している。共通テンプレートで可視化しており、異常発生時の初動確認もルール化している。

<a id="transition-3-4"></a>
### レベル3→レベル4 に進むには

**改善アクション（必須）**: 主要な指標に対して動的ベースラインによる異常検知を導入し、通常状態と異常状態を比較可能なグラフやアラート機能を整備します。あわせて、ダッシュボード上で異常兆候を視覚的に把握できる表示項目を追加します。

**活用アクション（推奨）**: 機械学習などの異常検知アルゴリズムを段階導入し、検知精度を高めていきます。また、障害検知時間などのKPIと指標を紐付けて、モニタリング設計自体を定量的に改善できる仕組みを整えます。

> **注意点メモ**: 動的ベースラインや機械学習導入時は、初期フェーズで過検知・見逃しが発生しやすいことを理解した上で、対象指標のチューニングや効果検証を繰り返しましょう。

<a id="level-4"></a>
## レベル4: 定量管理

**説明**

データ収集・可視化のパフォーマンスがKPIや統計的手法により定量的に測定・制御されており、プロセスの品質・精度の安定運用が実現されている。異常検知の精度や検出遅延なども評価対象となっている。

**具体例**

収集率・データ精度・しきい値調整頻度・アラート検出精度などをKPIで管理している。異常検知アルゴリズムの誤検知率・見逃し率を測定しており、継続的にモデルを改善している。

<a id="transition-4-5"></a>
### レベル4→レベル5 に進むには

**改善アクション（必須）**: 収集した監視データを活用し、リリース後のパフォーマンス変化や影響範囲を迅速に検知できる体制を整備します。さらに、機械学習による予測分析とAI技術を用いて、異常兆候の自動予測、影響範囲の推定、優先対応案の自動提示など、予測・最適化・対応提案を統合した仕組みを実装し、自律的な運用改善サイクルを推進します。

**活用アクション（推奨）**: 蓄積された監視データを活用し、各種KPIや信頼性指標（例：SLO）に基づく性能改善施策や障害予防施策を推進します。また、機械学習による障害予兆検知モデルの構築とAI技術を活用したパフォーマンス最適化提案を自動化する取り組みを進めます。

> **注意点メモ**: 高度な分析技術（機械学習・AI等）を導入後も、予測精度や誤検知率を定期的にモニタリング・改善し続ける必要があります。導入初期は過剰な期待を持たず、段階的にスコープを拡げるアプローチを推奨します。検知結果に対する人的レビューも、初期段階では併用することで制度定着を図ります。

<a id="level-5"></a>
## レベル5: 継続的最適化

**説明**

AI・機械学習による予測分析と最適化の仕組みが確立されており、改善提案から導入までが自動化されている。これにより、継続的改善が組織文化として定着している。

**具体例**

AIが収集データからトラフィックの急増を予測しており、ダッシュボードの構成変更やアラートルールの最適化を提案・自動実行している。運用側での介入を最小限に抑えつつ、改善活動を継続的に自動化している。
