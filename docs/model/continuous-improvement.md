# A6. 継続的な改善と最適化

**能力の定義**: モニタリングや開発プロセスのデータを活用し、チーム全体で継続的な改善を推進する能力。

<a id="level-1"></a>
## レベル1: 属人的

**説明**

改善活動は担当者の裁量に任されており、仕組み化されていない属人的な対応にとどまっている。

**具体例**

開発や運用の課題が発生しても、特定の担当者が個別に対応しており、組織的なフィードバックループが存在していない。過去の知見が蓄積されず、同じ問題を繰り返している。

<a id="transition-1-2"></a>
### レベル1→レベル2 に進むには

**改善アクション（必須）**: 障害発生時やリリース後には、簡易的な振り返り（例：What went well / What can be improved）を必ず実施し、発生した問題や改善点を記録します。記録はチーム内で共有し、継続的な運用改善に活用します。

**活用アクション（推奨）**: 振り返りで出た改善ポイントについて、次のスプリントやリリースで具体的なアクション（例：手順見直し、運用フロー更新など）に反映するサイクルを回し、継続的改善の第一歩を踏み出します。

> **注意点メモ**: 振り返りは形式だけで終わらせず、必ず「次に何を変えるか」を意識して行うことが大切です。小さな改善でもアクションに落とし込むことを重視してください。

<a id="level-2"></a>
## レベル2: プロセス確立

**説明**

レビューやふりかえりを定期的に実施し、課題や改善点をチームで共有する文化が形成されつつある。

**具体例**

開発チームが定期的に振り返りミーティングを実施し、プロセス上の課題を共有している。しかし、改善施策の優先順位が明確でなく、具体的なアクションに落とし込めておらず、同じ課題が繰り返し議論されている。

<a id="transition-2-3"></a>
### レベル2→レベル3 に進むには

**改善アクション（必須）**: 障害対応やリリース結果を定量的に振り返るため、基本的な運用指標（例：障害検知時間、復旧時間、リリース成功率など）を可視化し、チームで共有できるようにします。

**活用アクション（推奨）**: 収集した運用指標をもとに、チーム目標（例：復旧時間○分以内、リリース成功率○%以上）を設定し、振り返りの中で目標達成状況を評価・改善策を議論するサイクルを確立します。

> **注意点メモ**: 指標の数を増やしすぎず、まずは「行動につながる指標」を絞り込むことが重要です。見える化するだけで満足せず、必ず改善アクションに結びつける意識を持ちましょう。

<a id="level-3"></a>
## レベル3: 組織標準化

**説明**

チーム全体で改善プロセスが明文化・体系化されており、継続的改善がプロジェクトの一部として定着している。

**具体例**

開発速度、バグ修正率、デプロイ頻度などのKPIを設定し、その成果を定量的に測定している。これらの仕組みが組織として整備されており、継続的なプロセス改善を推進する体制を構築している。

<a id="transition-3-4"></a>
### レベル3→レベル4 に進むには

**改善アクション（必須）**: 定量データだけでなく、障害発生時の対応記録やリリース作業時のトラブル事例など、定性的な情報も収集・共有できる仕組みを整備します。改善事例をナレッジとして蓄積し、チーム内で学び合う文化を醸成します。

**活用アクション（推奨）**: 定量・定性の両面から運用の課題分析を行い、チーム横断で改善テーマ（例：検知プロセス最適化、復旧フロー効率化など）を設定し、改善プロジェクトとして推進します。

> **注意点メモ**: 定量指標だけでは見えにくい「現場感」や「背景事情」も大切にし、課題の本質を捉える意識を持つことが重要です。

<a id="level-4"></a>
## レベル4: 定量管理

**説明**

改善指標（KPI）やログデータを活用し、改善サイクル（PDCA）が測定・制御されており、成果も定量的に評価されている。

**具体例**

開発や運用のモニタリングデータを分析し、問題発生時には自動で改善ポイントを特定する仕組みを構築している。改善施策を定期的に実施し、最適化を標準業務として継続的に実行している。

<a id="transition-4-5"></a>
### レベル4→レベル5 に進むには

**改善アクション（必須）**: 運用や開発の各プロセスに対して、KPI達成状況や改善活動の効果を定期的に可視化・共有する場（例：月次レビュー、振り返り会）を設け、継続的改善を組織文化として根付かせる活動を始めます。さらに、改善対象や改善アクションの特定・提案・実行にAIを活用し、改善サイクルの自動化・自律化を段階的に進めます。

**活用アクション（推奨）**: 改善活動の成果を組織横断で展開するため、ベストプラクティス事例を共有し、他チームへの水平展開を推進します。改善施策の効果検証とフィードバックサイクルを確立し、全社的な改善文化の醸成を目指します。

> **注意点メモ**: 可視化や共有は「単なる報告」で終わらせず、改善活動を振り返り次のアクションにつなげる場にすることが重要です。成功事例と失敗事例の両方から学ぶ意識を持ちましょう。

<a id="level-5"></a>
## レベル5: 継続的最適化

**説明**

AIが改善対象やアクションを自動で特定・提案・実行し、最適なプロセス改善が自律的に実施されている。

**具体例**

AIが開発・運用データをリアルタイムで分析し、ボトルネック作業や非効率なプロセスを自動で特定している。リソース配分の最適化や不要な作業の削減を自動で行い、生産性向上やエラー削減に寄与する施策を人手を介さずに継続的に実施している。
